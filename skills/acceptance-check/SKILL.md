# 结营验收体检

## 一句话

**它检查的是：这个项目作为一个「交付物」的整体状态 —— 公网活着吗、真库能读能写且刷新后还在吗、接口边界行为对不对、该有的文档和 Skill 齐不齐、线上跑的是不是最新版。**

## 和 preflight-check 的区别

| | `preflight-check` | `acceptance-check` |
|---|---|---|
| **时机** | 提交/发布**之前** | 发布**之后** / 结营 / 交接 |
| **关注点** | 「别把脏东西推上去」（密钥、版本号、错误细节） | 「推上去之后，整体是不是好的」 |
| **范围** | 仓库卫生 + 公网接口可达 | 上述 + **真实写入持久化** + 交付物完整 + 版本一致性 |
| **写库** | 不写 | **会写一条再删掉**（验持久化） |

两个都跑，才是完整闭环。

## 五类检查

| 类 | 检查内容 |
|---|---|
| **A 公网可访问** | 首页 / 静态资源 / `/api/health` / 六个业务接口是否 200；数据源是否 `rest` |
| **B 真实读写 + 持久化** | 读基线 → 写入（201）→ 计数 +1 → **间隔 4 秒复读**（持久化）→ 防重复（409）→ 删除清理 |
| **C 接口契约与错误处理** | 405 / 501 / 400（缺字段、格式错）/ 错误不漏内部细节 / DELETE 幂等 / 405 是否带 `Allow` 头 |
| **D 本地交付物** | README、PRD、TECH_DESIGN、RUN、AGENTS、api-contract、rollback、两个 Skill 是否齐全 |
| **E 版本一致性** | 本地 `app.js?v=N` 与**线上实际加载的** `N` 是否一致 —— 抓「推了但没部署」 |

## 用法

```bash
# 完整检查（含公网 + 写库测试）
bash skills/acceptance-check/check.sh

# 只读，不写库（不想动生产数据时）
bash skills/acceptance-check/check.sh --skip-write

# 纯离线（只查本地交付物与版本号）
bash skills/acceptance-check/check.sh --offline

# 换域名
SITE=https://你的域名 bash skills/acceptance-check/check.sh
```

**退出码**：`0` = 全过（可能有 WARN）；`1` = 有 FAIL。

## 三种状态的含义

- `PASS` —— 明确通过
- `FAIL` —— 明确失败（退出码会变 1）
- `WARN` —— **值得知道但不阻塞**。例如：
  - 「线上版本落后」（说明改动没部署，不是 bug）
  - 「405 未带 Allow 响应头」（规范瑕疵，功能无影响）

**设计意图**：把「真的坏了」和「规范上可以更好」分开，避免 WARN 淹没 FAIL。

## ★ 写库的安全设计

这个脚本**会往真库写一条测试数据**（验持久化必须真写）。为不污染生产数据：

1. 写之前先读基线 `count`
2. 写完立刻把新行 id 登记到 `CLEANUP_IDS`
3. 注册 `trap cleanup EXIT INT TERM` —— **任何退出路径**（正常结束、报错、Ctrl+C）都会删掉
4. 最后复核 `count` 是否回到基线

> **为什么加 trap**：Day 28 第一次写这个脚本时，我不小心发了**两次 POST**（一次取 body、一次取状态码），
> 两次都写成功了但只删了第一条 → 真库残留一条脏数据（`id=87`）。
> 这个坑促成了两个改进：**① 只发一次请求（用 `-w` 同时取状态码和 body）；② 加 trap 兜底。**
>
> 所以如果你看到真库里多出 `note` 是「acceptance-check 探针」的行，说明某次运行被强杀了 —— 手动删掉即可。

## 为什么值得跑

这里的每一项都对应本项目**真实踩过的坑**：

| 检查项 | 对应的真实事件 |
|---|---|
| E 版本一致性 | Day 28：代码推了 GitHub，但 Render 没重新部署，线上仍是旧版 |
| B 持久化复核 | Day 19：写完以为成功了，实际没落库（数据源走了快照兜底） |
| A 数据源是 rest | Day 21：线上切 rest 之前，接口返回的是快照，看着正常但写入不持久 |
| C5 错误不漏细节 | Day 23：公网报错把内部信息漏出去了 |
| B 清理兜底 | Day 28：本脚本自己踩的坑（见上） |

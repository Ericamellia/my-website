## 四、板块③：最高优先级修复（P1 社团名全空）

### 4.1 定位

```javascript
// deploy/db/mappers.js · toWorkItem()
circle: r.circle_name,     // ← 读的是 circle_name
```

但**真库 `works` 表的实际列名是 `circle`**（快照文件 `deploy/data/*.json` 里也是 `circle`）。

→ `r.circle_name` **恒为 `undefined`** → JSON 序列化时丢掉 key → 接口返回里**根本没有 `circle` 字段** → 前端渲染「社团」时全空。

**实测确认（修复前）**：

```
music  6 件 / 社团空 6
doujin 6 件 / 社团空 6
game   5 件 / 社团空 5
video  6 件 / 社团空 6
art    7 件 / 社团空 7
─────────────────────
合计   30 / 30 全空
```

### 4.2 ★ 一个反直觉的关键发现（差点酿成事故）

第一反应是「那我把 `WORK_COLS` 里的 `circle_name` 也改成 `circle` 不就行了」。

**结果：线上 502 `upstream_failed`，后端直接挂掉。**

| 事实 | 说明 |
|---|---|
| PostgREST 里 select 写**不存在的列** `circle_name` | **不报错**，反而**返回了实际的 `circle` 列值** |
| select 改成 `circle` | 请求失败 → 502 |

> **所以正确的修法是：只改 mapper，绝不能改 `WORK_COLS`。**
> `WORK_COLS` 写 `circle_name` 反而是"对"的（PostgREST 宽容）。

**为什么要写下来**：这完全违反直觉 —— 「把错的列名改成对的」在这里恰恰是错的。如果不记录，下次很可能再踩。

### 4.3 修复（只改 1 个文件）

```javascript
// deploy/db/mappers.js · toWorkItem()
// ★ Day 27 修复：真库 works 表列名是 circle（不是 circle_name），
//   这条通道的 select 写的是 circle_name，导致 r.circle_name 恒为 undefined。
//   两种列名都读，三条通道（rest / pg / snapshot）都不会坏。
const circle = (r.circle_name !== undefined && r.circle_name !== null)
  ? r.circle_name
  : r.circle;
return {
  ...
  circle: circle,          // ← 原来是 r.circle_name
  ...
};
```

```bash
$ git diff --stat

 1 file changed, 9 insertions(+), 1 deletion(-)
```

**只改这一个文件**。`deploy/db/index.js` 的 502 改动已 `git checkout --` **完全回滚**，当前无 Day 27 改动。

### 6.2 ★ 走查中的一个重要纠正

第一次跑脚本时我用 `.fav-card-star` 选收藏按钮，返回 **`stars=0`**，一度以为是 bug。

**读代码后确认是设计如此**（`app.js:658`）：

```javascript
const favStar = opts.favStar ? `...` : '';
// 唯一传 favStar: true 的地方：

// app.js:1769（renderFav · 收藏页）
const makeCards = items => items.map(x => workCard(x, x._module, { idx: x._idx, favStar: true })).join('');
```

→ **卡片星标只在收藏页出现**；列表页的收藏入口**只有详情页**（`.detail-cta-fav`）。

**这正是"真实用户会卡住"的地方**：新用户看完列表想收藏，会发现**列表页没有收藏按钮**，得先点进详情页 —— 而页面上**没有任何提示**。
